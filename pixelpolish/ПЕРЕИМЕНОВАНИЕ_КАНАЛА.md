## Токена на этот канал нет и заводить его не понадобилось

Попытка 03.09 провалилась, потому что в OAuth Playground не была включена галка
«Использовать собственные учётные данные». Токен выпустился клиентом самого
Playground, наш `client_secret` его не обновляет:

```
POST https://oauth2.googleapis.com/token  ->  401 unauthorized_client
```

Признак, по которому это видно ДО обмена: на экране согласия Гугла написано имя
приложения. Стоит «Google OAuth 2.0 Playground» — значит клиент чужой и токен
будет мёртвый. Должно стоять имя нашего приложения.

Playground к тому же отзывает такие токены сам (в окне обмена написано 24 часа,
на экране согласия — 7 дней).

**Порядок действий, если токен когда-нибудь понадобится** — важен именно порядок,
на нём всё и сорвалось:

1. Сначала шестерёнка справа → галка «Используйте собственные учетные данные
   OAuth» → вставить `client_id` и `client_secret` из Cloud Console.
2. Только потом выбирать скоупы: `youtube`, `youtube.upload`, `youtube.force-ssl`.
3. Authorize APIs → аккаунт → **выбрать канал Years in a Minute**.
4. На экране согласия убедиться, что имя приложения НЕ «Google OAuth 2.0
   Playground».
5. Exchange authorization code for tokens → взять Refresh token.

**Но это не нужно.** Заливает ролики Седрак сам — так решено отдельно. Настройки
канала меняются раз в жизнь и уже стоят. Токен экономил бы редкие правки
описаний и обложек; 03.09 попытка его завести стоила полутора часов и ничего не
дала. Не начинать заново без ясной причины.
