# state/ — состояние проекта, которое обязано пережить любую машину

## used_photos_ledger.json

Какие пластины уже опубликованы. Секретов не содержит: идентификаторы Библиотеки
Конгресса, имена исходных файлов, id роликов и темы — всё это и так публично.

**Почему он здесь, а не только в `~/.config/youtube/`.** До 04.09 он жил в одном
контейнере и нигде больше. Это единственная защита от повторной публикации той же
пластины, и она была в одном экземпляре. 03.09 я поднял ложную тревогу, что реестр
потерял записи; проверка показала, что не потерял. Но сам факт, что проверять
пришлось по памяти и через API, а не по истории файла, — это и есть проблема.

Теперь у него есть история изменений и он переезжает вместе с репозиторием.

**Рабочая копия остаётся в `/root/.config/youtube/used_photos_ledger.json`** —
скрипты читают её оттуда. Эта копия синхронизируется руками при каждом обновлении
реестра. Расхождение между ними — повод разбираться, а не выбирать «который
свежее» на глаз.

## Чего здесь нет и не будет

Токенов, ключей приложения, api_key, cookies. Репозиторий публичный.
Учётные данные не переносятся текстом вообще: на новой машине они выпускаются
заново через `channels/oauth_flow.py` (device flow) и копируются из Cloud Console
владельцем. Через переписку они не проходят.
