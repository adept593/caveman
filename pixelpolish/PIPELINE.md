# Конвейер реставрации PixelPolish — спецификация

Цель, слово Седрака: **«фото после должно быть идеальным, как будто его сделали сегодня на современную камеру»**. До — грязное ч/б, после — цветное 4К. Ноль следов носителя, естественные цвета, живая фактура без пластика, ТЕ ЖЕ лица.

Требование Седрака 02.09.2026: **за один прогон**. Никаких кругов с приёмками посередине. Одна команда — готовая картинка.

    python run_all.py --src plate.jpg --out result/

---

## Почему одной ретуши мало

GFPGAN, BOPBTL, LaMa, DDColor — инструменты ретуши. Они ослабляют дефекты, но не создают фактуру. Кожа остаётся восковой, ткань — нарисованной, волосы — гладким шлемом. Потолок такого стека — «архивная реставрация», а не «снято сегодня».

Современную поверхность даёт только генеративный проход. Поэтому конвейер гибридный: `restore_v5` чистит носитель и хранит лица, ComfyUI даёт фактуру.

Лица при генеративном проходе закрыты маской и возвращаются композитом. Это не пожелание, а условие: подмена человека — брак независимо от красоты картинки.

## Этапы

### 0. Вход
Пластина любого размера. Поддержка JPEG/PNG/TIFF.
Логируется: исходный размер, EAN пластины, источник (для реестра прав).

### 1. Подготовка
1.1 Кроп самой пластины из футляра/рамки — `finish_v5.py:crop_plate`
1.2 Нормализация тона: снятие сепии, растяжка гистограммы по пластине, не по всему кадру
Выход: `01_prep.png`

### 2. Носитель — снять дефекты
Порядок важен: сначала машинная чистка по маске, потом ручные детекторы по остаткам.

2.1 BOPBTL detection → маска царапин и точечных дефектов
2.2 BOPBTL restore (`--Scratch_and_Quality_restore --HR`) → чистка носителя
2.3 `clean_v5b.py` → крапины и мелкие точки, зоны лиц исключены из масок
2.4 `stain_fix.py` → крупные разводы эмульсии, правится только низкочастотная составляющая, высокие частоты (плетение ткани, зерно) переносятся из оригинала
2.5 `lama_v5b.py` → дорисовка утрат эмульсии по маске; лица закрыты широкой маской

Выход: `02_clean.png`

**Известная поломка, которую чиним:** в старой цепочке `compose_v5b` шёл ПОСЛЕ clean/stain и затирал их результат своим носителем от BOPBTL (разные размеры кадра: 2204x2618 против 2654x3152). Вся чистка терялась. Правильный порядок — BOPBTL и композит лиц СНАЧАЛА, ручная чистка ПОТОМ.

### 3. Лица — сохранить личность
3.1 Детекция лиц: retinaface_resnet50 (есть в restore_v5) либо `face_yolov8m.pt` через Impact-Pack
3.2 GFPGAN v1.4, **weight 0.3–0.5, не выше** — при большем весе модель пересоздаёт черты: раскрывает глаза, сужает челюсть, «омолаживает». Проверено 03.09: на неполном прогоне лицо девочки было переписано.
3.3 Композит: восстановленные лица возвращаются в очищенный кадр с растушёванной границей

Выход: `03_faces.png` + `03_face_mask.png` (маска понадобится на этапе 4)

### 4. Фактура — современная поверхность  ← НОВЫЙ ЭТАП
Здесь появляется то, чего нет в старом стеке.

4.1 Маска запрета: маска лиц из 3.3, расширенная на 8–12 px, с растушёвкой 20 px
4.2 ControlNet (tile или lineart) по всему кадру — удерживает композицию, позы, границы объектов
4.3 img2img через `sd-v1-5-inpainting`, **denoise 0.25–0.35**, вне маски лиц
    - меньше 0.25 — фактура не появится
    - больше 0.35 — поедет содержимое: узор ткани, форма складок, детали фона
4.4 Композит: лица из этапа 3 возвращаются поверх результата

Выход: `04_texture.png`

**Риск этапа:** генеративный проход может выдумать фактуру, которой не было (03.09 нарисовал рогожу на брюках). Лечится снижением denoise и опорой ControlNet на исходную геометрию.

### 5. Цвет
5.1 DDColor → предсказывает только каналы **ab** в пространстве Lab; канал **L** берётся из нашего кадра. Поэтому яркость и черты не меняются вообще — модель может ошибиться в цвете, но не в форме.
5.2 `ab_scale` — подбирается, **не 0.45**. При 0.45 средняя насыщенность выходит 24.8, глазами это серо-сепия, а не цвет. Значение выбирается прогоном на 0.45 / 0.8 / 1.0 / 1.3 с замером насыщенности.
5.3 Коррекция тона кожи: не уходить в зелень и в розовое. Проверка по зонам лиц.

Выход: `05_color.png`

### 6. Финал
6.1 Апскейл до 4К через `UltimateSDUpscale` (тайлами, с фактурой), **не через Real-ESRGAN** — тот мылит и превращает узор в синтетическую сетку
6.2 Лёгкое зерно поверх — снимок без зерна читается как пластик
6.3 Резкость по маске, зоны лиц исключены

Выход: `final.png` (4К) + `collage.jpg` (до/после) + `crop_faces.jpg` (лица 100%)

## Автоматический контроль качества

Прогон завершается проверками. Не прошли — прогон помечается браком, картинка не идёт дальше.

| Проверка | Метод | Порог |
|---|---|---|
| Лица те же | эмбеддинг лица до/после, косинусная близость | ≥ 0.92 |
| Цвет появился | средняя насыщенность S в HSV | 45–90 |
| Не пересвечено | доля пикселей > 250 | < 1% |
| Фактура есть | дисперсия лапласиана по зонам ткани | выше исходной |
| Размер | длинная сторона | ≥ 3840 px |

Отчёт `report.json` со всеми метриками — рядом с результатом.

## Требования к оркестратору `run_all.py`

- аргументы: `--src`, `--out`, опционально `--denoise`, `--ab-scale`, `--gfpgan-weight`
- вызывает существующие скрипты через subprocess с явными путями; сами скрипты не переписывает без нужды
- каждый этап пишет свой промежуточный файл — чтобы при браке было видно, где сломалось
- лог: этап, время, размер выхода
- падение любого шага — остановка с указанием шага и текстом ошибки, без обхода
- `--batch <папка>` — прогон нескольких пластин подряд
- в конце печатает сводку и метрики контроля качества

## Чего в конвейере НЕТ и почему

**`bg_v5c.py` (пересборка фона через GrabCut)** — исключён. GrabCut принимает тёмные волосы за фон: срезает причёску, выедает плечо. Написан под кадр 626x757, на 3232x3840 пороги не работают. Либо переписывать с адаптацией к размеру, либо выбросить — фон и так пересобирается на этапе 4.

**Real-ESRGAN в финале** — заменён на UltimateSDUpscale. ESRGAN даёт мыло и синтетическую сетку вместо ткани.
